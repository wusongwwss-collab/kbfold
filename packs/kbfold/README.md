# packs/kbfold · KBFold 规则包（L0 通用模板与规则示例）

这是 KBFold 唯一的规则包，随开源版一起发布：**L0 两套通用模板 + 规则 DSL 全量示例**，全部字段带中文注释。六套行业模板不在此包（属于闭源的场景积累），但格式与本包完全一样——照着自己的行业写一份即可。

## 包里有什么

| 文件 | 说明 |
| --- | --- |
| `templates/project-stage.yaml` | L0 · 通用-项目阶段模板：一级目录按 00–07 八段编号（启动→规划→执行→监控→收尾→组合/资产/工具），行业不明但明显是长周期项目时的兜底形状（模板路由 C 级） |
| `templates/file-kind.yaml` | L0 · 通用-文件类型模板：一级目录按 01–12 十二类编号（计划/报告/记录/需求/设计/合同/流程/模板/沟通/评审/知识/交付），散文件模式的最后一道兜底（模板路由 D 级）——保证任何一坨文件都能得到「至少按类型分开」的结果 |
| `rules.example.yaml` | 规则 DSL 全量示例：`detect` 探测器（markers/keywords）、`paths` 路径规则、`@exclude`/`@inbox` 特殊去向、冲突裁决四条、通用名黑名单说明，全中文注释 |

两套模板的关系：同一批文件，两套视图各出一候选，由模板路由按优先级与判分取舍（行业不明时项目阶段视图优先）。**adopt 优先于 mkdir**：你已有的目录（比如一个 `合同/`）会被认作同类容器纳入体系，不改名不移动，只在真正的缺口处新建。

## 目录编号怎么长

- 一级目录按两位序号命名（`00-` 到 `07-` 或 `01-` 到 `12-`）；
- 同级新增目录取**最大序号 +1 自动补位**；
- 目录规模随文件量伸缩（模板内的 `scale` 段）：50 个文件以内只长 3 段、目录总数 ≤ 12 个；50–500 个长 4–6 段；500 个以上才用八段全集。少文件建几十个空目录，是「工具比资料还重」——阈值是工程判断，觉得不对直接改模板，不用改代码。

| 档 | 谁提供 | 怎么到 |

| **60 分 · 开箱即用** | 开源版本地 | 装完零依赖、零配置、零账号：L0 两套模板兜底，`plan / apply / undo / search` 全链路可用，断网可用。`npx kbfold plan <演示目录> --demo` 30 秒看到第一份判定报告 |

## 改模板流程

1. 改 YAML（`kbfold.yml` 或模板文件）——纯文本，可 diff、可回粘；
2. `kbfold validate` 校验结构（通用名黑名单命中、字段错误、版本不符都会在这里拦下，不产生半套结果）；
3. 重跑 `kbfold plan` 看差异——diff 能指出「因为规则变了，哪几个文件归属会变」；
4. 满意后 `kbfold apply`；不满意，规则文件粘回去就行，什么都没发生过。

## 反馈与社区

改出的更好规则以结构化 delta（规则结构与参数，不含内容）回灌社区，按季度合入；脱敏要求与贡献流程见仓库根目录 `CONTRIBUTING.md`。反馈通道默认关闭，说明见 `docs/FEEDBACK.md`。
