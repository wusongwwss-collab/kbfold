# 反馈与隐私（FEEDBACK）

> KBFold 的匿名改进反馈是**可选**能力：默认关闭，开启也只上行统计与结构信息，原文永不出本机。本文说明三档反馈各自上行什么、本机怎么脱敏、服务端怎么二次把关、以及怎么开怎么关。

## 1. 三档定义

| 档 | 状态 | 上行内容 | 说明 |
| --- | --- | --- | --- |
| **L0** | **关（默认）** | 无 | 零网络调用。整备台不发起任何外连；`kbfold audit` 的外部端点清单为空（或仅本地嵌入模型端口），可当场自证 |
| **L1** | 点选评价 | **被拒绝的归档建议（三态点选）**：你在 `_inbox/` 或报告里对建议的「采纳 / 否决 / 改判」点选，附被否建议的判定信号摘要（信号级别、置信区间）。**不含路径、不含文件名** | 我们最想知道的是「哪类建议总被否」——这是规则改进最值钱的信号 |
| **L2** | ＋计数与结构 | ① **模板命中率**：各模板 / 各规则通道的命中计数、置信级分布、`_inbox` 积压量级（纯计数）；② **规则 delta**：你改动过的规则结构与参数（字段级「改前值→改后值」，不含任何业务内容）；③ **目录结构指纹**：目录树归一化指纹——**只上行 hash，不上行原始目录名 / 文件名** | 帮我们看清「大家把模板改成什么样」，按结构改进默认模板 |
| **L3** | ＋失败样例 | **本地脱敏后的失败样例**：判定明显不对的案例，经本机槽位化处理、残留检测通过后才上行 | 样例的价值在于结构，不在于内容 |

**开启是逐档叠加的**：L2 包含 L1 的内容，L3 包含 L2。任何档位都**永不上行**：文件名、目录原名、文件内容、路径原文、人名、公司、金额、电话、邮箱。

## 2. 本机脱敏：PII 槽位化

上行前，脱敏先在你本机完成（反馈 SDK 内置，不依赖任何第三方库）：

1. **槽位化**：中文语境正则识别手机号、金额、人名、公司名、邮箱等具体值，替换成 `<PHONE_1>`、`<AMOUNT_2>` 这类**类型槽位**——上行报文里只有「这里有个电话」的事实，没有电话本身。
2. **目录名槽位化**：结构指纹计算前，目录名先归一化成类型槽（日期 / 合同 / 编号 / 通用名 …），再对槽位树算 hash。**hash 不可逆**，原始目录名不进报文。
3. **原文残留检测**：上行前最后一道闸——对报文做未槽位化 PII 模式检测（明文电话 / 金额 / 邮箱等），**命中即拒绝上行**并在本机记录拒绝原因，宁可少上行一条，不漏上行一段原文。

## 3. 服务端二次校验

上行端点只接受脱敏后的结构化数据，并有四道服务端闸：

1. **拒原文**：任何包含文件内容、路径原文、未脱敏具体值（人名 / 公司 / 金额 / 电话）的载荷一律**拒收并丢弃**——客户端漏了，服务端兜住。
2. **拒超限**：超出字段白名单或长度上限的载荷拒收。
3. **幂等**：每条上行走事件去重，网络重试不会造成重复记录或重复计数。
4. **限流**：按来源限流，超限请求拒绝；上行内容仅用于规则与模板改进统计，不用于任何内容存储与二次分发。

## 4. 开关方式

```
kbfold feedback on      # 开启（首次开启时选择档位；默认进入 L1）
kbfold feedback off     # 关闭：恢复零外连，audit 端点清单回到空
kbfold feedback show    # 查看上行记录：逐条列出每次上报的时间、类型与脱敏后内容摘要
```

- **首启问一次**：第一次 `plan` 成功后询问一次「是否开启匿名改进反馈」，之后不再问；不开启照常能用全部功能。
- **随时可关**：关闭后不再有任何网络请求；已上行的匿名数据可申请删除。
- **上行记录本机可查**：无论当前开关状态，历史每次上报的时间与内容摘要都可在本机逐条核对——上传了什么，一目了然。
- 反馈落盘在独立配置目录（不在 `.kb/` 内）：删除该目录即回到「从未询问」的初态，不影响库本身。

## 5. 社区回灌

你改出的更好规则以**结构化 delta**（规则结构与参数，不含内容）沉淀回社区；回灌按季度合入并在更新日志标注「含社区改进 N 条」。贡献流程见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
