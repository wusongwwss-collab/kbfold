# KBFold · 知识库整备台

> 一个改错了能一键退回去的知识库整备台。把散乱的项目资料编译成知识库。

**v0.1.0 已发布**（2026-11-01）：零依赖判定内核、CLI 四命令、MCP 服务器、L0 模板与反馈 SDK 全部在本仓库。

## 它做什么

- 扫描你的项目资料目录，判定每个文件该归哪个库、哪一层，产出可预览的重整计划
- 先看后动：`kbfold plan` 预演，`kbfold apply` 才落盘，每一步都记进追加式日志，`kbfold undo` 一键整批退回
- 判定不猜：置信度不够的直接进 `_inbox/` 摊开候选，不硬归类
- 全文检索：语义 + 全文 + 关键词三路融合，每条结果都带 `[n]` 引用编号
- 默认零风险：只读扫描、删除能力不存在（代码里没有删文件调用）、除本地嵌入模型外零外连

## 快速感受

```bash
npx kbfold plan <你的资料目录> --demo
```

（npm 包已发布：[npmjs.com/package/kbfold](https://www.npmjs.com/package/kbfold)；克隆本仓库则直接 `node bin/kbfold.js …`。）

## 快速开始：5 分钟走完第一遍（断网可跑通）

> **环境底线**：Node.js 20 及以上（推荐 22，22 才自带 `node:sqlite`，20 上全文索引自动降级）。
> 零安装路径 `npx kbfold …`（npm 包为 Node 壳），或克隆仓库后 `node bin/kbfold.js`；判定内核由 Python core 承担，机器上需另备 **Python 3.10 及以上**。
> 壳首次运行自动定位系统 Python（Windows 依次尝试 `py -3` / `python` / `python3`，其余平台依次 `python3` / `python`）；未安装 Python 时打印官方下载指引（https://www.python.org/downloads/）并以退出码 2 结束。
> 零 API key、零账号、零数据库服务；除可选的本地嵌入模型外，这 5 分钟不发起任何网络请求。

| 时间 | 你做什么 | 你会看到什么（唯一可信的验收） |
| --- | --- | --- |
| 第 0–1 分钟 | `git clone <本仓库> kbfold` 并进入目录 | 首屏与目录树；`examples/demo/fixtures/` 里有约 1000 个文件的合成假目录 |
| 第 1–2 分钟 | 跑不改任何东西的预演：`node bin/kbfold.js plan ./examples/demo/fixtures --demo` | 三块输出：现状统计（多少能判定 / 待归 / 被排除）、疑似知识库（每条带置信与原因）、平手清单——演示目录故意放了三组打平的目录，**第一次跑就会看见 `_inbox/`** |
| 第 2–3 分钟 | 问一个「为什么」：`kbfold explain <任一文件>`；再跑 `kbfold audit` | explain 报出命中层级与依据；audit 的外部端点清单为空——「零外连」当场自证，不用信文档 |
| 第 3–4 分钟 | 第一次看得见的变化：`kbfold apply ./examples/demo/fixtures --rename-only`（只改名，不搬家） | 文件名当场变规整；末尾打出批次号与退路命令 `kbfold undo <批次号>`；目录结构未动、未跨目录移动任何文件 |
| 第 4–5 分钟 | 打开 `packs/kbfold/rules.example.yaml` 与 `packs/kbfold/templates/` 浏览规则与模板全貌（全字段中文注释） | 你已站在「改模板」的入口：改一行词表重跑 `plan` 即见差异；想反悔就 `kbfold undo <批次号>`——「改错了能一键退回去」在这 5 分钟里被兑现了三次（plan 零写入 / rename 可整批退 / 模板可 diff） |

## 四个能力

| 能力 | 命令 | 它做什么 | 边界 |
| --- | --- | --- | --- |
| **扫描** | `kbfold plan`（只读） | 只读遍历目录，产出现状统计（可判定 / 待归 / 被排除）与乱度指标、疑似知识库清单（每条带置信与原因） | 只读文件元信息，不读文件内容；运行前后源目录逐字节一致 |
| **匹配** | `kbfold.yml` + 规则 DSL | 四层信号（显式标记 / 名称 / 结构 / 类型）判分，L0–L6 判定梯命中即停；置信不足进 `_inbox/` 并附候选 | 规则打平不猜；`data`、`docs` 这类通用目录名写进规则启动即报错 |
| **方案** | `kbfold apply` | 按预演计划整批落盘：既有目录优先 adopt（不改名不移动）而非 mkdir；`--rename-only` 只改名，`--move` 需二次确认并打印受影响文件数 | 先记账再动手；中途失败整批停，不留半成品 |
| **回滚** | `kbfold undo <批次号>` | 按追加式日志逆序回放，逐步 hash 校验，冲突即停、不覆盖 | 撤销本身也是一条日志记录；历史永不被改写 |

## 三条承诺，逐条可实测

这三条不是口号，每条都给了验证方法：

1. **只读扫描**：`plan` 全程零写入。用你自己的比对工具验证：跑前后源目录逐字节一致。
2. **plan–apply–undo 闭环**：apply 结束当场打印批次号；undo 逆序回滚、逐步校验；撤销后目录与动手前逐字节一致。每一次撤销本身也记进日志，历史可回放。
3. **零外连**：`kbfold audit` 列出本次运行用到的全部外部端点，正常情况下列表为空（或仅本地嵌入模型端口）。删除能力不存在：代码里没有删文件的调用，可自行检索验证。自查方法与漏洞上报渠道见 [SECURITY.md](SECURITY.md)。

## 开源版与商业版差在哪

开源版干净地做完「建库」这一件事；「用起来」的深水区在商业版。

| 能力 | 开源版（本地单机规则） | 商业版（云端批量语义 + 行业体系） |
| --- | --- | --- |
| 归属判定 | 规则 DSL + 信号判分 + 判定梯，全部本地；规则接不住的长尾进 `_inbox/` 等人 | 云端对 `_inbox/` 长尾做批量语义判定，结果回流本地确认 |
| 模板体系 | L0 两套通用模板（项目阶段 / 文件类型）+ 自改自建 | 六行业模板包 + 行业词表基线 + 按行业定制目录体系 |
| 证据来源 | 文件元信息（路径 / 名称 / 扩展名 / 显式标记），不读内容 | 增加会议证据源等私有信号，库随使用自己长大 |
| 检索 | 本地三路融合（语义走本地嵌入模型可选 / 全文 / 关键词），单库 | 云端大库语义检索、跨库跨项目问答 |
| 协作 | 无账号、无同步、无冲突合并（`.kb/` 是目录，同步交给同步盘） | 团队共享库、权限、多机协同 |
| 归档生命周期 | 三档生命周期**只算不动**，清单给用户 | 批量归档执行、跨机归位、合规保留策略 |
| 反馈通道 | 三样匿名统计（默认关），社区回灌季度一次 | 同通道 + 云端聚合，行业基线持续校准 |

一句话：开源版给你一台判定准确、随时可退的整备台；商业版把「等你看的待办」变成「已经做完的活」——语义接管长尾、行业模板替代手写规则、会议证据让库自己长大。

**开源面**＝判定内核、规则 DSL、L0 两套通用模板、库格式公开规范、CLI 与 MCP 壳、反馈 SDK、全部测试；**闭源面**＝六行业模板包、会议证据源、云端聚合与批量语义、企业托管与协同。

## 反馈与隐私

- **默认关闭**。第一次 `plan` 成功后会询问一次「是否开启匿名改进反馈」，之后不再问；不开启也照常能用全部功能。
- **开启后上行什么**（只有三样统计与结构信息）：① 你拒绝过的归档建议（只记「建议归到哪被你否了」，不含文件名）；② 各模板命中占比（纯计数）；③ 目录结构指纹（目录名先在本机替换成类型槽位再计算）。详见 [docs/FEEDBACK.md](docs/FEEDBACK.md)。
- **永不上行什么**：文件名、目录原名、文件内容、路径原文。上传动作发生前，脱敏与槽位化先在你本机完成，原文永不出本机。
- **随时可关**：`kbfold feedback off`；`kbfold feedback show` 逐条查看上行记录；关闭后恢复零外连，已上行的匿名数据可申请删除。

### 反馈命令速查（v0.2.0）

| 命令 | 作用 | 联网 |
| --- | --- | --- |
| `kbfold feedback on [L1\|L2\|L3]` | 开启反馈并选档位（默认 L1；写同意位 `.kbfold/state.json`，打印「上行什么/永不上行」对照） | 否 |
| `kbfold feedback show` | 待上行逐条可看：级别 / 内容摘要 / 时间 /「尚未发送」态，含本地拒收留痕与已发回执提示 | 否 |
| `kbfold feedback send` | **唯一联网动作**：先逐条打印最终脱敏形态，y/N 确认后才上行；成功写回执码 `.kbfold/sentreceipts/` | 是 |
| `kbfold feedback off` | 关闭反馈，恢复零外连（写 90 天静默标记） | 否 |
| `kbfold feedback clear` | 清空本地待上行记录（不需联网；已发回执与同意位保留） | 否 |

`send` 可靠性语义：每条带独立 nonce 幂等键与 HMAC 签名头（密钥 env `NW_OSS_FEEDBACK_HMAC`；端点 env `NW_OSS_FEEDBACK_ENDPOINT` 可覆盖，缺省 `https://www.easurwork.cn/api/oss-feedback/v1`）；服务端拒收（422，reason 码如 `whitelist:result` / `residue:phone`）的记录本地标 `rejected` 并**永久跳过**；网络/服务端故障（5xx/超时）指数退避重试 ≤3 次，失败不推进游标、下次续发；发送后 30 天内可凭回执码到 https://www.easurwork.cn/open-source/feedback 申请删除。脚本/CI 等非交互环境须显式 `--yes`（stdin 非 TTY 且缺 `--yes` 时退出码 4，绝不静默上行）。
